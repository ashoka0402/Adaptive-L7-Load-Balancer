# Pulse architecture

The default FastAPI runtime is a single-process L7 proxy. Live Mode registers trusted independent HTTP applications via a JSON/YAML route file, never generates traffic, and reserves /pulse/ for management. Demo Compose starts three separate workload containers performing real SQLite queries and CPU computation. Operators can register their own origins by editing the route file and restarting. No publicly exposed management or arbitrary URL registration is supported.

The data plane uses longest segment prefix routing, bounded admission and safe retries, connection pooling, active health checks (or passive-only if no health path), and circuit breakers. EWMA feedback measures actual upstream header arrival time; outstanding requests penalize congested nodes; cold-start, stale and periodic exploration keep observations fresh. Backend assignment counters and successful response share are distinct. Proxy response completion latency, selection microseconds, upstream header latency and approximate event loop tick lag are distinct measurements. Request X-Ray samples one in twenty requests plus the first; no path, request body or headers are retained. The topology animation represents recent successful-response share, not individual requests.

Laboratory Mode is explicit (--lab), preserving fault injection, scenario comparisons, scaling, canary, incident replay and resilience controls. Origins use independent child processes with bounded shared fault state; load generators run in separate subprocesses. No lab traffic is emitted in live mode. The lab is not a production orchestration system.

The adaptive proof runner uses actual paced HTTP from a separate process against separately started SQLite/CPU applications, changes only one origin's CPU work, records raw requests and phase boundary health, and compares Round Robin with EWMA over normal/degraded/recovery phases. No benchmark result is implied by the implementation. The older aiohttp runtime and historical measurements are preserved for comparison.
