# Pulse architecture

The default runtime is the FastAPI application in app/fastapi_lb. It ports the upstream codedpool/load-balancer design to Python while retaining the previous aiohttp implementation for comparison. The default demo boots four real loopback HTTP origins and the proxy uses HTTPX network requests; the control plane uses reserved local same-origin endpoints. A segment trie matches the longest path prefix, each route has a pool of eligible backends, and the proxy uses fixed admission limits, health probes, circuit state, bounded retry tokens and streaming responses. Telemetry is per process and bounded, with SSE snapshots and Prometheus metrics.

Run one worker only. The dashboard's traffic dots are aggregate animation. The arena compares real HTTP workloads but is not a reproducible production benchmark. No automatic scaling or distributed shared state is claimed. The token-free management surface is for local access only; bind to loopback or use the existing loopback Docker port mapping.

## Experiment layer

The active FastAPI demo adds an Experiments controller above the proxy and local HTTP origin lifecycle. It coordinates mutually exclusive bounded benchmark tasks; the existing shared topology and proxy are exercised with actual network requests. Fault injection is application-level. Scaling is event-loop-local with a two-to-six-replica bound, cooldown and drain-before-remove. Canary uses a deterministic percentage allocation to a separate versioned local origin, with optional staged promotion and rollback. Routing traces retain only candidate metadata and status, not request URLs, headers or bodies. Recording stores 240 snapshots in memory. The experiment UI uses the same scrollable document, four navigable sections and a separate JS asset. External configured origins do not expose these lab controls.
